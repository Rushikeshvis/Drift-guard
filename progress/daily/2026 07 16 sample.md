### PROPOSED: concepts.md
```markdown
## Ranking Functions Comparison
- ROW_NUMBER(): Unique sequential number (1, 2, 3, 4).
- RANK(): Ties get same rank; next rank is skipped (1, 2, 2, 4).
- DENSE_RANK(): Ties get same rank; next rank is not skipped (1, 2, 2, 3).
- Syntax: Functions take no arguments: RANK() OVER(...)

## LAG() and LEAD()
- LAG(col, n): Accesses data from n rows prior.
- LEAD(col, n): Accesses data from n rows subsequent.
- Syntax: LAG(column) OVER (PARTITION BY ... ORDER BY ...)

## PERCENT_RANK()
- Definition: Relative rank of a row as a percentage (0 to 1).
- Rule: ASC order = lowest value is 0. DESC order = highest value is 0.
```

### PROPOSED: mental_models.md
```markdown
## Window Function vs Subquery
- Situation: When you need to calculate an aggregate but keep the original row count.
- Wrong Mental Model: "I need to aggregate, so I must collapse rows (GROUP BY) or use a subquery."
- Better Mental Model: "Window functions are 'side-calculations' that preserve the original table dimensions."
- Decision Rule: If the output requires the same number of rows as the input, do NOT use a subquery. Use OVER().

## Global Window Operations
- Situation: When you need to rank or aggregate across the entire dataset.
- Wrong Mental Model: "I must define a PARTITION BY to use a window function."
- Better Mental Model: "PARTITION BY is optional. Omitting it creates a single, global window."
- Decision Rule: If the calculation is not scoped to a specific group, omit PARTITION BY.
```
